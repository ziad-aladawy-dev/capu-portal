# Permission System — Multi-Role Scope Resolution & CRUD Overhaul

## Decisions (confirmed with user)
- **Client-side computation** for role contributions (no backend changes)
- **Compact pips** visualization (5-dot rating style)

## Problem Statement

When a user has multiple roles that modify the same permission with different scopes, the current UI doesn't clearly show:
1. Which role grants what level at what scope
2. How multiple roles combine for the same resource
3. The effective permission at each scope level

**Example:**
- Faculty Admin → Dashboard → Edit → Scope: Faculty of Engineering
- Academic Advisor → Dashboard → View → Scope: Faculty of Science
- Department Head → Dashboard → Delete → Scope: CS Department

## Current Backend (already correct)
- `StaffRoleAssignment` → staff + role + structural scope + temporal scope
- `StaffPermissionOverride` → per-action override with its own scope
- Effective = (role allows ∪ override allows) − (role denies ∪ override denies) per ScopedResourceKey

## Implementation Plan

### 1. Compute roleContributions in PermissionsEditor

No backend changes. Use existing `assignment.roleAssignments` + `tree[].resources[].permissions[]` to compute which role grants what at what scope.

Key logic:
- For each role assignment, check which permissions that role grants on each resource
- Group by resource, showing each role's contribution with its scope

### 2. Update resource card JSX

Replace flat level selector with:
1. Role contribution cards (compact pips + role name + scope badge)
2. Effective level selector (existing pills)
3. Override section (if any)

### 3. Add CSS for contribution cards

Compact pips (5 dots), role name, scope badge — minimal space, clean look.

### 4. Verify all CRUD operations

- Create/Update/Delete roles ✓
- Assign/Remove roles with scopes ✓
- Create/Revert overrides ✓
- Multi-role + multi-scope scenarios ✓
